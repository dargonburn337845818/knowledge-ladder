## 二、绝对禁止事项（硬约束）

1. **禁止任何云端 API**：运行时不得调用 Codeforces、DMOJ、AtCoder、OpenAI、本地大模型等任何外部推理服务。
2. **禁止本地大模型推理**：不允许 ONNX、Llama、Ollama、transformers 等任何模型加载。
3. **只允许本地计算**：
   - 加减乘除
   - `Math.log2` / `math.log2`
   - 数组遍历、排序、归一化
4. **最终点拨话术严禁出现具体算法名**：
   - 严禁出现：前缀和、差分、线段树、树状数组、单调队列、二分、DP、FFT、并查集、Dijkstra、SAM 等。
   - 只能使用四类方向语言：编码压缩、传播松弛、剪枝决策、变换域映射。
5. **界面极简**：问题流中永远只出现：
   - 一个问题
   - 三个大按钮：是 / 否 / 不确定
   - 一个入口：我感觉不对劲
   - 不显示已答轨迹，不显示四方向标签。
6. **先有基线暴力，后有四大策略**：四大方向必须在自动收敛或异常打断之后才能出现。

## 三、数据文件

### 3.1 `algorithm_prior.json`

包含：

```json
{
  "params": {
    "entropy_stop_threshold": 0.45,
    "ig_stop_threshold": 0.03,
    "detector_entropy_threshold": 0.30,
    "anomaly_surprise_threshold": 0.85,
    "uncertain_decay": 0.5,
    "max_questions": 12,
    "baseline_required": true
  },
  "algorithms": [
    {
      "algorithm_name": "二分答案",
      "prior_probability": 0.006,
      "cf_tags": ["binary search"],
      "dmoj_types": ["Divide and Conquer"]
    }
  ]
}
```

`algorithms[].prior_probability` 是初始候选池权重。

### 3.2 `feature_algorithm_matrix.json`

包含：

```json
{
  "features": [
    {
      "id": "monotonic",
      "dimension": "排查",
      "question": "答案或可行性判定具有单调性，可以二分吗？",
      "kind": "extra"
    }
  ],
  "directions": ["编码压缩", "传播松弛", "剪枝决策", "变换域映射"],
  "algorithms": [
    {
      "algorithm_name": "二分答案",
      "profile": {
        "monotonic": 0.85,
        "metric_bool": 0.9,
        "dependency": 0.15
      },
      "direction_weights": {
        "剪枝决策": 1.0,
        "编码压缩": 0.05,
        "传播松弛": 0.05,
        "变换域映射": 0.05
      }
    }
  ]
}
```

`profile[feature_id]` 是 `P(该特征为真 | 该算法)`，取值范围 0~1。

## 四、核心状态机

### 4.1 状态

```
baseline -> question -> finished -> direction
```

- `baseline`：用户确认“已经先想了暴力/模拟方案”。
- `question`：动态计算并显示下一个 IG 最大的问题。
- `finished`：自动收敛或异常打断，显示四大方向大按钮。
- `direction`：用户点击某个方向后，显示模糊话术。

支持：

- `back`：回退到上一个问题前的快照。
- `restart`：清空会话，回到 `baseline`。

### 4.2 baseline 规则

- 问题文案：“你已经先想了一个暴力/模拟方案吗？”
- 答案“是”：进入 `question`。
- 答案“否”或“不确定”：停留在 `baseline`，显示提示：
  > “请先写一个最直接的暴力/模拟方案，再继续拆题。”
- 不显示任何四方向信息。

## 五、熵减引擎算法

### 5.1 候选池

- 候选 = 所有 `algorithm_prior.json -> algorithms`。
- 初始 `weights[i] = prior_probability[i]`。
- 每次回答后做贝叶斯更新，得到后验分布。

### 5.2 信息增益选择问题

对每个未问特征 `q`：

```
P(yes) = Σ_i weights[i] * profile[i][q]
P(no)  = 1 - P(yes)
```

回答“是”后的后验：

```
w_y[i] = weights[i] * profile[i][q]
w_y[i] /= Σ_j w_y[j]
```

回答“否”后的后验：

```
w_n[i] = weights[i] * (1 - profile[i][q])
w_n[i] /= Σ_j w_n[j]
```

熵：

```
H(P) = - Σ_i P[i] * log2(P[i])
```

期望后验熵：

```
E[H_after] = P(yes) * H(P|yes) + P(no) * H(P|no)
```

信息增益：

```
IG(q) = H(P) - E[H_after]
```

每步选择 `argmax IG(q)` 且未被问过的问题。

### 5.3 用户回答的更新

- 点“是”：

```
w[i] = w[i] * profile[i][q]
w[i] /= Σ w
```

- 点“否”：

```
w[i] = w[i] * (1 - profile[i][q])
w[i] /= Σ w
```

- 点“不确定”：

```
w_yes[i] = w[i] * profile[i][q] / Σ
w_no[i]  = w[i] * (1 - profile[i][q]) / Σ
w[i] = 0.5 * w_yes[i] + 0.5 * w_no[i]
w[i] /= Σ w
```

### 5.4 自动停止条件

满足任一条件，立即进入 `finished`：

1. `H(P) < entropy_stop_threshold`
2. 剩余所有未问问题的最大 `IG < ig_stop_threshold`
3. 已问数量达到 `max_questions`
4. 用户点“我感觉不对劲”且 `H(P) < detector_entropy_threshold`

### 5.5 人类探测器

- 用户点“我感觉不对劲”，若熵低于阈值：立即进入 `finished`。
- 若熵还高：显示提示：

  > “先再回答 1–2 个问题，让范围收小；如果仍然觉得不对，再点‘我感觉不对劲’。”

- 每次回答后计算“惊讶度”：

```
surprise = P(user_answer | current_pool)
```

- 若 `surprise < anomaly_surprise_threshold`，标记一次反常，并可选显示：

  > “这个回答和当前推测有点反直觉；如果觉得不对，可以点‘我感觉不对劲’。”

### 5.6 四方向概率

对每个方向 `d`：

```
P(d) = Σ_i weights[i] * direction_weights[i][d]
```

在 `finished` 页按 `P(d)` 降序显示大按钮。

## 六、UI 改造要求

### 6.1 移动端（`mobile/www`）

- 在 `app.js` 中新增熵减状态机，或新开 `entropy_engine.js`。
- 把静态 `STEPS` / `recommend()` / `hints()` 替换成动态状态机渲染。
- 保留 `style.css` 现有玻璃拟态与 Editorial 主题。
- 四个方向标签只出现在 `finished` / `direction` 阶段，点击后打开话术。
- 数据通过 `window.ENTROPY_DATA` 内嵌，避免运行时 fetch；或从本地 `data.js` 扩展。

### 6.2 桌面端（PySide6）

- 新增 `entropy_engine.py`，加载两个 JSON。
- 修改 `main.py -> DissectPage`：
  - 状态：`baseline` / `question` / `finished` / `direction`
  - 问题流只渲染一个问题和三个答案按钮
  - 保留 `FlowDiagram`、`OP_INFO`、引导式思考页，但只在 final/direction 使用
- 回退使用快照栈。

### 6.3 话术库

不能提具体算法，只给模糊方向。示例：

- 编码压缩：重复信息提前存好 / 把状态压缩成更小表示 / 预处理换查询。
- 传播松弛：沿着依赖关系一层层推 / 状态从前驱传递过来。
- 剪枝决策：排除大批不可能候选 / 利用单调性一次砍掉一半。
- 变换域映射：换坐标系 / 差分、对偶、重表述 / 把纠缠结构转成熟悉模型。

最终话术模板示例：

> “你的路径已经收敛到信息冗余较高的区域。可以考虑把重复计算提前存储（编码压缩），或者顺着状态传递关系一层层推（传播松弛）。但这里可能有一处隐蔽异常，试试换一个坐标系（变换域映射）去破局。”

## 八、测试验收标准

1. 打开软件先看到“基线暴力确认”，答“否”不能进入问题流。
2. 问题流只显示一个问题 + 是/否/不确定 + 我感觉不对劲。
3. 问题顺序不是固定四步，而是按 IG 动态变化。
4. 最终页只出现四大方向，不出现“二分”“单调队列”“前缀和”等算法名。
5. 点“我感觉不对劲”在低熵时立即打断；高熵时只提示。
6. 移动端与桌面端行为一致。
7. 断网运行仍完整可用（纯本地 JSON）。
