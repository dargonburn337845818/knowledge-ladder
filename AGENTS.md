# Knowledge Ladder · Project Guide for Agents

> Short guide for AI/agents and new contributors. Public behavior is locked by
> `tests/`; data files are public interface inputs.

## What this is

A **local-first entropy-based problem dissection tool** for competitive
programming. No network, no LLM, no telemetry. It asks one information-gain
maximizing question at a time and converges to four directions.

## Entry points

- Desktop: `main.py` → `app.window.MainWindow`
- Mobile PWA: `mobile/www/index.html`
- Mobile data generator: `export_mobile_data.py`
- Core engine (Python): `entropy_engine.py`
- Core engine (JS): `mobile/www/entropy_engine.js`

## Module map

| Path | Responsibility |
|---|---|
| `entropy_engine.py` | Python entropy state machine; precomputed profile columns |
| `info_framework.py` | Information-theory labels for algorithms |
| `knowledge_data.py` | 120 algorithm name registry |
| `tiers_data.py` | 8-tier knowledge tree |
| `teacher_consensus.json` | Uncalibrated teacher guidance (display only) |
| `expert_content/` | Versioned expert direction content: cards/layers/edge cases + schema |
| `app/direction_content.py` | Four-direction content data layer (desktop loader / legacy bridge) |
| `app/` | PySide6 deep modules: theme/state/utils/dialogs/tier/dissect/window/wallpaper |
| `mobile/www/` | Offline-capable PWA and Capacitor web assets (app.js / entropy_engine.js / card_store.js / entropy_data.js) |
| `scripts/` | Dev/CI tools: data schema, engine parity, release body |
| `pyproject.toml` | Project metadata + ruff/mypy/pytest config |
| `.github/workflows/` | CI, Android APK, Desktop EXE |
| `wallpaper-export` repo | Wallpaper Engine export tool (independent repo) |

## Hard constraints

1. **Privacy**: no runtime network calls, no external fonts, no analytics.
2. **Local data**: `docs/`, `reports/`, `preview/`, `系统提示词.txt` and
   builder inputs are ignored and must never be committed.
3. **Interface stability**: public methods of `EntropyEngine` and the JS
   `EntropyEngine.create()` return shape are tested; do not break them.
4. **Dual engine parity**: change `entropy_engine.py` and
   `mobile/www/entropy_engine.js` together.
5. **Generated file**: `mobile/www/entropy_data.js` is generated by
   `export_mobile_data.py`; CI checks it is in sync.

## Verification

```bash
python -m unittest discover -s tests -v
ruff check .
mypy --ignore-missing-imports entropy_engine.py info_framework.py knowledge_data.py \
  tiers_data.py export_mobile_data.py app/teacher_consensus.py
python scripts/check_data_schema.py
python export_mobile_data.py                            # keep data in sync
python scripts/engine_parity.py
node --check mobile/www/entropy_engine.js
node --check mobile/www/app.js
node --check mobile/www/card_store.js
node --check mobile/www/sw.js
node tests/test_card_store.js
QT_QPA_PLATFORM=offscreen python -c "...MainWindow smoke..."
```

## Workflow conventions

- `main` is protected; changes go through PRs.
- GitHub Actions must keep `contents: read` by default and only elevate for
  release jobs.
- Do not add secrets to workflow files; use GitHub Secrets only when needed
  (currently none are required).
